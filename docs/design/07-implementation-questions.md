Все вопросы мастер-документа закрыты. Здесь собраны вопросы, которые появились при переносе
дизайна на движок Factorio 2.1: где API помогает, где мешает и что нужно решить. Коды `I*` —
по аналогии с разделом «Вопросы».

Проверено по файлам Factorio 2.1.24 (headless, с Space Age) и его `changelog.txt`.

## I1 — Независимость модулей и межпланетные зависимости

**Проблема.** По концепции каждый модуль ставится отдельно. Но в «Техах планет» записано:
Echaris ← Nivar (нивалит), Echaris ← Solaris (жаропрочные кристаллы). Если игрок поставил
Echaris без Nivar, рецептам Echaris не из чего делаться.

**Сейчас в коде.** В `space-age-plus-echaris/info.json` Solaris и Nivar — необязательные
зависимости (`?`): они грузятся раньше, если установлены, но не обязательны.

**Варианты.**
1. *Запасной рецепт (рекомендую).* Если Nivar нет — у рецепта Echaris другой ингредиент
   (например, сверхпроводник Фульгоры вместо нивалита). Модули остаются независимыми.
2. *Жёсткая зависимость.* Echaris требует Nivar и Solaris. Проще, но ломает концепцию.
3. *Тех без зависимостей.* Технологии Echaris с нивалитом просто не появляются без Nivar.

## I2 — Мусор из выброшенных предметов

**Реализуемо.** В Factorio 2.1 есть `LuaSpacePlatform::ejected_items`,
`eject_item()` и `clear_ejected_items()`. План: раз в N тиков читать `ejected_items` каждой
платформы, записывать в `storage.debris[маршрут][сегмент]` по `platform.distance` (0..1 → 10
отрезков) и очищать список. Когда платформа на отрезке — создавать на её поверхности
куски-астероиды (собственные прототипы `asteroid-chunk`), которые ловит обычный сборщик
астероидов. Статический `asteroid_spawn_definitions` для этого не подходит: он не зависит от
того, что выбросили, поэтому спавн делаем скриптом.

## I3 — Качество технологий и бонус к постройке

**Проблема.** У технологий в Factorio нет качества. Пять качеств — это пять отдельных
прототипов на каждую технологию (`…-normal`, `…-uncommon`, …, `…-legendary`). Цена ×1/×1.5/×2/×3/×5
делается легко. «Разблокировал редкую — открылись необычная и обычная» — тоже, скриптом.

Сложность — **«постоянный пассивный бонус к постройке»**. У технологий есть только
фиксированный набор эффектов, бонуса «к конкретной постройке» среди них нет.

**Варианты.**
1. *Продуктивность рецептов (рекомендую).* Эффект `change-recipe-productivity` (+X% к
   рецептам, которые открывает технология). Работает из коробки, видно в интерфейсе.
2. *Качество постройки.* Технология лучшего качества открывает рецепт постройки, который сразу
   даёт её более высокого качества (необычная, редкая, …). Бонус реальный, но смешивается с
   механикой качества Space Age.
3. *Скриптовый бонус.* Например, скорость машины через скрытые маяки. Гибко, но тяжело для
   производительности и непрозрачно для игрока.

## I4 — Скрытое дерево, дешифратор, ЛЛК

**Реализуемо.** Технологии с `enabled = false` и `visible_when_disabled = false` скрыты.
Дешифратор открывает их скриптом (`force.technologies[name].enabled = true`), дальше их
обычным образом исследуют в лаборатории. Окно с тремя карточками — собственный GUI.
Дешифратор — постройка-сборщик с картой данных и колбами в качестве ингредиентов: когда цикл
завершается, скрипт показывает окно выбора. ЛЛК — то же, с шансом 10-20% и выбором из двух.

Внимание: если скрыть ванильные технологии, нужно проверить, что не сломаются ачивки и
сценарий начала игры (обломок корабля на Наувисе).

## I5 — Телескоп и спутники

**Реализуемо.** Планеты в Space Age и так скрыты, пока технология с эффектом
`unlock-space-location` их не откроет. «Силуэт» и «название без деталей» движок не показывает,
поэтому это делается в нашем GUI или дневнике, а `unlock-space-location` срабатывает только на
уровне «Разведана спутником 2». Спутник 1 поколения — отдельный предмет с
`send_to_orbit_mode = "automated"` (как ванильный спутник); результат запуска обрабатывает
событие `on_rocket_launched` (шанс найти, счётчик запусков до спутника 2).

## I6 — Буря Echaris

**Постройки на 50-70%.** Реализуемо: `LuaSurface::global_effect` (чтение/запись) задаёт
эффект скорости для всей поверхности. Стабилизатор, фундамент, ЭМИ-экран защищают зону — для
этого нужен скриптовый пересчёт или скрытые маяки только внутри зоны.

**Дроны теряют навигацию.** Прямого API «сбить навигацию» нет. Варианты:
1. *Урон и разряд (рекомендую).* Вне защищённой зоны во время бури дроны получают урон и теряют
   заряд. Mk2 со встроенной защитой — не теряют.
2. *Скорость.* У дронов вне зоны сильно падает скорость.
3. *Отключение.* Роботодоки вне зоны не выпускают дронов (через `disabled_by_script`).

## I7 — Перегрев Solaris

**Реализуемо скриптом.** Встроенной механики перегрева нет (есть только замерзание на Аквило).
Предлагаю считать нагрев по зонам (чанкам), а не по каждой постройке. Радиаторы снижают
нагрев своей зоны. Стадии «нормальная → горячая → критическая → сломана»: на «критической»
постройка отключается через `disabled_by_script`, на «сломана» получает урон.

## I8 — Криобуря и стадии замерзания Nivar

**Частично встроено.** На планете можно включить `entities_require_heating = true`, как у
Аквило: постройки замерзают без тепла. Но у движка только два состояния: «работает» и
«замёрзла». Стадии «холодная → промёрзшая → остановлена → сломана» и обогрев 2 уровня (обычный
и крио) делаются скриптом поверх. Предлагаю: обычное замерзание — движок, криобуря — скрипт,
который во время бури считает обычный обогрев недостаточным вне криокупола.

## I9 — Пещеры Nivar

**Реализуемо.** Пещеры — отдельная поверхность (`game.create_surface`) со своей генерацией.
Лифт — пара сущностей на двух поверхностях, ресурсы передаются через `linked-container`,
игрок перемещается через `teleport`. Важно для кислорода: у такой поверхности нет `planet`,
поэтому в ядро нужно добавить регистрацию поверхностей пещер (сделаю вместе с модулем Nivar).

## I10 — Клавиша дневника

**Проблема.** По документу дневник открывается на Tab. В Factorio 2.1 Tab — это стандартное
действие «подтвердить сообщение» (ванильный обломок корабля с ним связан).

**Варианты.**
1. *Своя клавиша, по умолчанию J (рекомендую)* + кнопка на панели быстрого доступа.
   Клавишу игрок может поменять.
2. *Оставить Tab.* Будет конфликтовать с подтверждением сообщений.

## I11 — Коронарная масса и торнадо

**Реализуемо, переиспользуя механику молний Фульгоры.** На планете задаются
`lightning_properties`, а «зонтик» и «приёмник» — постройки типа `lightning-attractor`
(приёмник даёт энергию, как громоотвод). Число лучей 1-5 — параметр настройки модуля
(`sap-solaris-coronal-rays`, уже добавлен). Торнадо Aquara — подвижная сущность со скриптом;
штормовой якорь — тот же `lightning-attractor`, к которому скрипт тянет торнадо.

## I12 — Захват ульев SA+

**Реализуемо.** В Space Age у гнезда есть поле `captured_spawner_entity`, ракета захвата — это
`capture-robot-rocket`. «Перекалибровка» — отдельная ракета для каждой планеты; её снаряд
захватывает только гнёзда этой планеты. Корм — свой предмет по рецепту документа (биофлюс
Глебы + термит + магматит и т.д.). Малый шанс порчи улья в криобурю (H3) — скрипт на
`on_entity_died`/захват.

## I13 — Кислород при первой посадке

**Проблема.** Персонаж прилетает на новую планету в капсуле, распределителя там ещё нет.
Баллона по умолчанию хватает на 3 минуты (малый — 1 мин). Этого может не хватить, чтобы
поставить распределитель, подвести энергию и кислород.

**Варианты.**
1. *Льготный период (рекомендую).* После первой посадки на планету баллон не тратится
   N минут (настройка, по умолчанию 5). При хардкоре «Строгий кислород» льготы нет.
2. *Баллоны как предмет.* Запасные баллоны в инвентаре, их можно привезти с собой.
3. *Оставить как есть.* Игрок сам везёт распределитель и кислород в бочках.

## I14 — Расходники коллектора на планетах SA+

По документу: Echaris — ЭМИ-фильтр, Aquara — осушитель, Nivar — криоконцентратор. Solaris —
только генератор. Рецепты добавляются в модулях планет через
`sap.oxygen_collector_recipe(planet, pressure, ingredients)` из ядра, когда у планет появятся
прототипы и давление атмосферы.
